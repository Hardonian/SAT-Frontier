# EPYC real pilot and follow-on: evidence audit

The pilot and follow-on contain respectively 6 and 8 recorded runs, all reported exact with zero incomplete cubes. Each instance's exact fraction agrees across its recorded depths within each study. An independent audit of the records checked that every result's exact cube fractions sum to its recorded aggregate and that CSV and JSONL row counts agree. The preserved checks report was independently reproduced from the original, unmodified evidence: the signed-weight barbell result matches a separate exhaustive factor calculation; grid results match prior recorded exact results, which are not independent solver checks. Input hashes match the instance manifest. These are consistency checks, not a general correctness proof.

The barbell's true/false weights include 3 and -2; its resulting `62068225398921/10` is a signed weighted sum, **not a network reliability probability**. It cannot be compared to a differently weighted historical barbell. These are small, single-run measurements, not statistically supported speedup claims or an industrial benchmark. Logs report an interleave strategy, but this is not independent proof NUMA binding was applied. Peak RSS reported by the runner should not be assumed to include aggregate worker memory.

## Provenance and privacy

Both recorded `source-hashes.json` files match all corresponding Git file bytes at commit `62f09fc`; that commit is an ancestor of publication base `52ac611`. This describes the runner sources, not a claim that the experiments ran at the publication base. The study `SHA256SUMS` files are the **original** checksum manifests: all 261 pilot and 1306 follow-on entries were verified against the untouched local originals before publication. The checks directory's original checksums also passed. Original raw evidence remains in the source worktree.

For privacy, absolute home and interpreter paths were replaced in 28 copied result and log files only; computation records and all other files are retained. Consequently, the original `SHA256SUMS` files intentionally do not pass against these redacted copies. Each study's new `PUBLISHED-SHA256SUMS` covers all files in its published directory except itself, including the unchanged original manifest; run `sha256sum -c PUBLISHED-SHA256SUMS` inside each study. The original checks report and verifier describe the original, unredacted evidence; its verifier expects the original study checksums and therefore is not directly runnable against redacted copies without adaptation. The checksum manifest provides byte integrity, not proof of correctness or provenance by itself.

No later or currently running campaign is included. A targeted scan of the publication files found no common credential patterns or remaining absolute home paths; such scans cannot prove absence of all private information.
