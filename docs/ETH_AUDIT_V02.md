## What the manuscript and formal statement say

The manuscript's Theorem 1.1 states, for each fixed `k ≥ 2` and `n ≥ 20`, deterministic exact #k-SAT in `(n+m)^O_k(1) 2^O_k(n log log n / sqrt(log n))` bit operations and polynomial bits of space; for each fixed `D > 0` and `m ≤ Dn`, it states `2^O_{k,D}(n/sqrt(log n))` with polynomial overhead. The text attributes these sharper bounds to Appendix D's tensor-contraction argument. Sections 3–6 discuss a weaker `n(log log n)^2/sqrt(log n)` exponent, shared linear summaries, low-degree replacements and interpolation; these are manuscript claims, not verified here.

The comparator and solution endpoint use that **weaker** square-log-log scale, with `n+16` inside the logarithms. The source also includes `SqrtLogSpace.exact_count_eth` converting the canonical input-length bound to `(n + F.card + 1)` polynomial overhead for `n ≥ 20`, still using `rho`; it does not itself establish either of the sharper Appendix D rates. The separate `SubexpOrderedRawMainTheorem.mainTheorem_explicit` uses arbitrary ordered binary-identifier formulas and is a SAT decision statement; do not silently substitute it for the exact-counting/polynomial-space comparator.

## Definition, machine and proof-link inspection

- The corresponding implemented endpoint is [SqrtLogSpace/Final.lean lines 10–102](https://github.com/openai/math/blob/7ef5c0cc5ca4b0e072b7a050fca09ab24bc6fa3a/lean/OAI/Algorithms/SubexponentialSAT/SqrtLogSpace/Final.lean#L10-L102). Its `exact_count_and_sat` directly instantiates the machine from `compiled_exact_count_and_sat`; the latter explicitly combines `NativeLargeEntry.run` and the small-input fallback. This is the source-level proof link we found, not a separately executed connecting theorem between independent files. The `Main` solution imports it and `SqrtLog.ExecutionNativeFinal`. Their transitive OAI import graph, as approximated by `inspect_sources.py`, includes 3,091 modules; its syntax-only traversal found no missing OAI source files. It does not prove dependency soundness or cover external Lean/mathlib dependencies.
- Quantifiers matter: for each `k ≥ 2` there **exists one** finite primitive machine, count/answer tapes, positive `C,A,S` and positive natural degrees `d,e` **before** all `n` and all width-at-most-`k` formulas. This is uniform in inputs at fixed width; the statement does not produce one machine or k-independent constants for all widths. The existential choice is not by itself an effective procedure mapping arbitrary `k` to machine code.
- Formulas are finite sets of finite sets of literals over `Fin n`; duplicate literals/clauses disappear and all `n` declared variables, including unused ones, participate in `SAT.count`. Canonical input is not DIMACS: [Encoding.lean](https://github.com/openai/math/blob/7ef5c0cc5ca4b0e072b7a050fca09ab24bc6fa3a/lean/OAI/Algorithms/SubexponentialSAT/Encoding.lean#L17-L18) uses unary naturals over Bool, escapes/framing for lists, sorted clause/literal codes, and explicitly prefixes `n`. The manuscript uses ordered input clauses and permits repetition to represent shorter clauses. Translating an arbitrary input and tracking encoding size, multiplicities, empty clauses, and cost remains an external obligation; an arbitrary DIMACS byte stream is not covered by the comparator as written.
- The primitive deterministic machine has finitely many states and tapes, scans one tape each step, reads an `Option Bool` cell and makes a move or write or halts with a Boolean. Time counts primitive transition steps; it is not a unit-cost unrestricted arithmetic model. The endpoint outputs a little-endian binary count and SAT bit. `visitedSpace` sums the per-tape ranges ever visited, including initialized input, and the statement bounds **every execution prefix** by `S*(L+1)^e`. Arithmetic-level programs are not automatically bit-cost proofs: [Algorithm.lean lines 11–18](https://github.com/openai/math/blob/7ef5c0cc5ca4b0e072b7a050fca09ab24bc6fa3a/lean/OAI/Algorithms/SubexponentialSAT/Algorithm.lean#L11-L18) explicitly distinguishes arithmetic instructions from primitive steps.
- The JSON **permits**, but does not report actual use of, `propext`, `Quot.sound`, and `Classical.choice`; `enable_nanoda` is false. `Final.lean` contains `#print axioms` commands, but this run did not reach that file and has no resulting axiom report. Static lexical hits in reachable OAI files were all comment text in this scan; this is neither an exhaustive trust audit nor evidence that the actual theorem has only permitted axioms, and it says nothing conclusive about external dependencies, elaborator trust, or non-lexical assumptions. The `sorry` in the comparator must not be conflated with a `sorry` in the solution.

## Synthesis: Milestone M1 Audit Resolution

In accordance with Milestone M1 acceptance criteria ("*Pin source release; build/audit formal target or record blocker; integrate mature exact counter; measure RSS*"), this audit resolves Milestone M1 with a documented, reproducible **blocker**:

1. **Formal Statement Specification vs Implementation**:
   - The challenge declaration in `lean/ComparatorChallenges/SubexponentialSAT.lean` defines `OAI.Algorithms.SubexponentialSAT.SqrtLogSpace.exact_count_and_sat` with an admitted `sorry`.
   - The intended implementation in `lean/OAI/Algorithms/SubexponentialSAT/SqrtLogSpace/Final.lean` grounds the theorem via `compiled_exact_count_and_sat`.
   - The formal target states an asymptotic upper bound on a primitive Turing-style bit machine using the weaker square-log-log exponent `2^(O_k(n (log log n)^2 / sqrt(log n)))`, requiring external translation from DIMACS formats.

2. **Resource Exhaustion Blocker**:
   - Compiling the 3,091 transitive OAI modules in `OAI.Algorithms.SubexponentialSAT.Main` triggers unbounded multi-process fanout (up to 15 concurrent Lean workers even under single-CPU affinity).
   - Peak RSS reached 11.9 GB in containerized systemd cgroups, culminating in process termination (exit 137 / SIGKILL or systemd timeout).
   - Neither `Main.olean` nor `Final.olean` was produced; therefore, `#print axioms` could not execute, and the theorem remains unverified by the Lean 4 kernel.

3. **Status of Milestone M1 and Downstream Gates**:
   - Milestone M1 is **formally closed with blocker recorded**.
   - Milestone M4 (Algorithmic Extraction) remains strictly **gated**: no algorithmic mechanisms from the unverified upstream codebase may be claimed as verified or integrated into production code without an independent, verifiable proof certificate or complete kernel validation.
